# Upstream provenance

Provider development in Asterism is upstream-first. Before implementing a
provider, add every donor and research source here and in
`research/providers/<provider>/`.

An audited donor capability with a clear implementation, protocol behavior or
reliable behavioral evidence is implementation scope by default. Product
authorization decides whether a caller may use it; Provider audit does not drop
it because it changes completion/progress/score, submits answers, is
non-idempotent, or requires BrowserBridge, Capture, browser runtime state,
dynamic crypto material or local authentication assistance. The engineering
flow is `audit -> semantic mapping -> Rust/clean-room implementation -> Core
capability -> fixture/native-or-browser boundary -> verification -> live
validation`. Reliability invariants still apply at every step.
